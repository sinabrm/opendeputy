# OpenDeputy roadmap

OpenDeputy is preparing its first public source and Windows preview. The roadmap records direction, not a promise of dates. Work is tracked through repository issues and the OpenDeputy project board.

## Public-source launch

- Publish contributor, support, conduct, security, and issue-reporting documentation.
- Keep the dependency audit and generated third-party license inventory clean.
- Protect the default branch and enable GitHub security reporting and dependency alerts.
- Verify a fresh Windows x64 source setup, production build, and packaged installer.
- Make the repository and planning board public only after the launch checks pass.

## First Windows preview

- Publish an unsigned Windows x64 pre-release with SHA-256 checksums.
- Verify installation, upgrade, uninstall, first-run provider setup, and recovery behavior on a clean Windows environment.
- Document known limitations and collect reproducible feedback through GitHub Issues.

## After launch

- Improve contributor onboarding, issue triage, accessibility, and release automation.
- Continue security, dependency, and performance maintenance.
- Evaluate portability work without weakening the supported Windows desktop experience.

See the [OpenDeputy project](https://github.com/users/sinabrm/projects/9) for current Priority, Size, and Status fields. New work begins in Backlog and moves through Ready, In progress, In review, and Done.
